## Execution order

2. Implement camera, readable expansion, layout stability, and rendering improvements (B1–B3).
3. Finish orientation, navigation, accessibility, and mobile interaction (C).

6. Verify every requirement on the assembled product, stage the site, regenerate references, and document the result (E2).

## Product decisions

- Preserve the warm dark palette, typography, rounded connectors, and progressive exploration.
- Keep the current renderer while correcting the measured defects. ELK is evaluated as a development experiment before any runtime dependency is introduced.
- Ordinary expansion prioritizes readable choices and spatial continuity. Overview is an explicit mode with a clear return to readable detail.
- Use generic fixtures for layout and performance experiments. Preserve existing domain graph topology and command content.
- Source review and taxonomy/link availability are separate facts. Existing entries remain explicitly unreviewed unless there is documented evidence supporting a narrower review claim.
- The work covers educational accuracy, source traceability, software integrity, and interface quality. Operational exploitation procedures and attack-route validation are outside this implementation.
- Completion means a tested local build and deployment-ready artifact. Publishing to the live site is a separate action.

## Acceptance targets

- Interrupting camera motion adds only the user's intended movement, including embedded-container and touch cases.
- Ordinary expansion keeps a comfortable reading scale (at least 0.9× with 14 px titles), with a compact list when the full branch cannot fit.
- Typical arrangement settles within about 360 ms; entrance stagger stays within 100 ms and never grows with graph size.
- Reduced-motion preferences apply at startup and when changed during a session.
- Typical 25-node fixtures hold approximately 60 Hz locally. Measure and report 100-node behavior; avoid environment-sensitive FPS assertions in CI while enforcing deterministic work/duration bounds.
- All authored applicability notes and aliases survive presentation. Searchable saved notes and theme selection survive reload.
- Every named graph-integrity invariant has a meaningful negative assertion.
- Chromium and Firefox browser checks, narrow viewport checks, and accessibility checks cover the changed interactions.
- Generated references agree with current content, and the deployment artifact excludes tests, package dependencies, developer fixtures, and review artifacts.
